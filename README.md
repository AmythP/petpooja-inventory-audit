# Automated Kitchen Inventory Reconciliation & Variance Audit Engine

> An enterprise-grade Python audit automation system that eliminates food/raw material shrinkage, automates POS/ERP reconciliation, and enforces daily stock variance controls across commercial kitchens and hospital hospitality operations.

---

## 🚀 Overview & Business Impact

In multi-unit food and hospitality operations, discrepancies between POS recorded consumption, warehouse receipts, and physical counts create significant unaccounted food cost shrinkage (5–12% of total inventory).

This system provides a fully automated **one-click audit engine** that:
- Ingests raw HTML/Excel transaction exports directly from **Petpooja POS/ERP**.
- Reconciles **Daily Production Consumption**, **Procurement / Inward Transfers**, and **Operator Adjustments** against actual on-floor physical stock.
- Calculates mathematical **Stock Variances** using strict accounting rules:
  $$\text{Expected Closing Stock} = \text{Opening Stock} + \text{Inward Transfers} - \text{Production Consumption} + \text{Adjustments}$$
- Automatically flags **Shortages (Theft/Spillage)** vs. **Excesses (Unrecorded Inward/Recipe Deviations)** with zero manual calculation overhead.
- Implements state persistence, multi-tab audit views, conditional formatting, and historical trend logging.

## 🛠️ Architecture & Features

```
                   +----------------------------+
                   |  Petpooja POS / ERP Data   |
                   |  (HTML .xls + Stock .xlsx) |
                   +-------------+--------------+
                                 |
                                 v
+---------------------------------------------------------------+
|               Inventory Audit Engine (Python Core)            |
|                                                               |
|  - HTML Parser (Streamlined Table & Frameset Ingestion)       |
|  - Fuzzy Name Mapper (POS SKU to Internal Master Ledger)      |
|  - State Engine (Preserves manual edits, rolls over dates)    |
|  - Dynamic Excel Compiler (OpenPyXL formulas & cell styles)   |
+---------------------------------------------------------------+
                                 |
                                 v
                   +----------------------------+
                   |  production+closing.xlsx   |
                   |  (Dynamic Multi-Tab Ledger)|
                   +----------------------------+
                                 |
         +-----------------------+-----------------------+
         |                       |                       |
         v                       v                       v
 [Sheet1: Audit]        [DAILY CHECK: Ops]      [FOR PRINT: Exec]
  - Physical Count       - Shift Handover        - Management Ready
  - Auto-Reasons         - Historical Log        - Formatted Matrix
```

### Key Technical Capabilities
1. **Zero-Dependency Extraction**: Built-in `HTMLParser` handles malformed or nested HTML-as-XLS exports commonly generated by POS systems.
2. **Fuzzy String Matching & Normalization**: Maps varying raw material naming schemes across purchase orders, recipes, and warehouse ledgers.
3. **State & Mutation Persistence**: Safely preserves user-entered data (physical counts, purchase slips) on multiple runs within the same operational day without overwriting.
4. **Automated Rollover**: Seamlessly rolls over the previous day's verified physical closing stock into the next day's opening stock.
5. **Dynamic Excel Formula Generation**: Emits active formulas (`='DAILY CHECK'!B2`, `IF(...)`, `ROUND(...)`) rather than static values, allowing floor supervisors to perform real-time "what-if" adjustments inside Excel.

## ⚡ Quick Start

### 1. Requirements
- Python 3.10+
- `openpyxl >= 3.1.2`

```bash
pip install -r requirements.txt
```

### 2. Execution
Place your POS consumption `.xls` and stock status `.xlsx` into the working directory and run:

```bash
# Windows
run_inventory_audit.bat

# Linux / macOS / Manual
python src/run_inventory_audit.py
```
